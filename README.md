# 棋弈 · BoardGames

八款浏览器小游戏：五子棋、中国象棋、日本将棋、国际象棋、中国军棋、九路围棋，以及推箱子和华容道。棋类支持同一设备上的本地双人和人机对弈，益智游戏支持单人解谜。无需账号，游戏逻辑与 AI 都在本地执行，不调用付费服务。

[打开棋弈](https://soyungs.github.io/BoardGames/)

## 本地开发

使用 Node.js 22.12+ 和 npm。

```sh
npm ci
npm run dev
```

```sh
npm run lint
npm test
npm run build
npm run preview
```

测试通过 Node 内置测试运行器执行，使用项目已有的 TypeScript 转译器加载源码，无额外测试框架依赖。测试文件串行执行，使有真实时间预算的 AI 测试不与其它搜索争抢 CPU。

## 玩法与规则边界

| 游戏 | 本作规则 |
| --- | --- |
| 五子棋 | 15×15，自由连珠，黑先白后，五子及以上连线获胜，无禁手；满盘无胜者为和棋。 |
| 中国象棋 | 支持马腿、象眼、炮架、将帅照面、将军、将死与困毙；困毙判负。暂不裁定长将、长捉及重复局面。 |
| 日本将棋 | 9×9，持子打入、金将六向、进出敌阵可选升变、强制升变、二步限制、打步诘限制与王手判定。暂不裁定千日手及持将棋。 |
| 国际象棋 | 支持王车易位、吃过路兵、兵升变为后/车/象/马、将死与逼和。暂不裁定五十回合、重复局面与子力不足和棋。 |
| 中国军棋 | **6×12 简化暗棋变体**，每方25子。后两行（行营留空）和前线5格随机布阵，军旗在大本营，地雷在后排。道路仅上下左右；铁路可直行，工兵可转弯；行营内棋子不可被攻击，本营内棋子不可移动。暗子只在交战后亮明，夺旗或令对方无合法走法获胜。 |
| 围棋 | **9×9 快速变体**，黑先，提子、禁自杀和简单劫。连续两次停着后，按棋子与围空的面积计分，白贴6.5目。混色边界的空区为中立；结束时不自动判定死子，须先提净死子。简单劫仅禁止立即还原上一手棋盘，不使用全局超级劫。 |
| 推箱子 | 方向键、WASD或屏幕按钮移动，只能推不能拉。所有箱子进入目标即过关；支持选关、撤销、重开与步数/推数统计。 |
| 华容道 | 经典4×5「横刀立马」，点选棋子后使用方向键、WASD或屏幕按钮滑动。曹操到达下方中央出口获胜，单格移动计一步，支持撤销和重开。 |

人机模式由内置算法执行。棋类 AI 使用浏览器 Web Worker，思考期间仍可重开和操作页面；重开、离开对局会终止旧计算。搜索有时间预算，在时限内保留已完成的最佳结果；实际等待还包括 Worker 启动时间，设备较慢时会略有增加。当前棋类悔棋支持本地双人；刷新或离开游戏会清空当前进度。

将棋规则参照[日本将棋联盟对局规则](https://www.shogi.or.jp/match/taikyoku_rules/)；象棋困毙判负可参照 [GNU XBoard 象棋规则说明](https://www.gnu.org/software/xboard/whats_new/rules/Xiangqi.html)。围棋基础概念可参照[英国围棋协会入门规则](https://www.britgo.org/intro/intro2.html)，本作的计分与终局范围以上表为准。

## AI 强度与速度

- 五子棋识别连五、冲四、跳四、远处活三及组合威胁，按威胁排序并逐层搜索。
- 国际象棋、中国象棋与将棋使用迭代加深、alpha-beta剪枝、局面缓存和吃子交换搜索；先检查立即获胜、失子与反吃风险，排除不能合法回吃的钉住棋子。应将与安静将军也进入战术搜索；国际象棋的短时限退路也筛查对手的一手将杀，优先评估即将升变的兵，升变会区分将死与逼和。
- 军棋依据已公开的敌子、布阵位置与移动轨迹推断可能身份，权衡进攻收益、损失风险及军旗保护，决策时不读取敌方暗子的真实身份。炸弹双亡、失去机动子与铁路转弯后的身份推断分别处理。
- 围棋结合提子、救打吃、连接、切断、气与影响力，在有限候选中搜索；识别真眼与假眼、远处提子救棋，并避免吃小子后遭到倒扑而丢掉更多棋子。

四种较复杂搜索默认计算预算800ms，围棋上限650ms，军棋通常会提前完成。搜索中断时优先保留已完整评分的走法；国际象棋、象棋、将棋与军棋的显式极短预算保留25ms战术检查底线。来不及完成战术筛查时仍返回合法备用着，极短预算不能保证排除所有一手威胁。各棋类落子前延时140ms；所有计算在Worker中执行，异常时4秒超时退出并显示重开提示。预算用于控制算法耗时，并非对任何设备都保证相同的总响应时间。内置AI适合练习，时间受限的搜索仍可能错过较深的战术。

## 界面与动画

- 暖白、木色和深绿界面，大厅提供棋类/益智筛选及双人/电脑快捷入口。插画、国际象棋棋子和将棋木牌由本地SVG绘制，不依赖外部图片或字体服务。
- 每款游戏前置目标与分步操作提示；深绿轮廓标出选中棋子，绿点标出空位走法，金圈标出可吃子或军棋交战目标。围棋可点击棋块查看气，详细规则可展开阅读。
- 页面淡入淡出、筛选布局过渡、落子弹簧、棋子轨迹与到达光晕、吃子退场、箱子推动与滑块移动及短暂的结束庆祝。特效不阻挡点击，重开/悔棋/选关会清除旧效果，淡出页面立即停止接收输入。
- 棋盘随容器缩放，SVG、棋子与按钮使用同一坐标系，手机默认可完整看盘；也可选择「放大查看」以阅读棋子并精确点击。
- 支持系统「减少动态效果」偏好、键盘操作、焦点提示及回合和选子状态播报。拼图撤销与重开保留键盘焦点，升变面板关闭与结束面板重开后会恢复稳定焦点。

## GitHub Pages

应用使用 HashRouter，静态站点路径与 `#` 后的游戏路由独立。

仓库 Settings → Pages 将 Source 设置为 GitHub Actions。现有 workflow 会在 PR 中执行 lint、规则测试和生产构建，推送 `main` 或 `master` 后执行检查并部署。

构建仓库子路径时：

```sh
VITE_BASE=/BoardGames/ npm run build
VITE_BASE=/BoardGames/ npm run preview
```

`VITE_BASE` 仅控制资源路径，不要将它用作 HashRouter 的 `basename`。
